# Mods for BO2 Requiem NX (Beta 3.2 / 0.3.2)

[Português (Brasil)](README.pt-BR.md)

Everything goes in `/switch/t6game/` on the SD card. The `sd/` folder here already follows that layout.

## Zombies aim assist in multiplayer

```
python3 patch_mp_aimassist.py /path/to/t6mp.nro
```

Patches the file in place and leaves `t6mp.nro.bak`. The script finds the instructions by signature and refuses versions where they do not match. After a game update, run it again on the new `t6mp.nro`.

Enables the aim snap when pressing ZL, lock-on (the reticle follows the target while you move the stick) and an auto-aim range for weapons that have 0. Keep **AIM ASSIST** enabled in Controls → Gamepad.

The aim snap only works in matches against bots: also copy `sd/switch/t6game/scripts/mp/aim_assist_bots_only.gsc` to `/switch/t6game/scripts/mp/`. The patch only enables auto-aim while this console is the server and the script says every other player is a bot (or plays on the same console, in split screen). When a human from outside joins, it turns off within 1 s. When you join someone else's match it stays off. Without the script, auto-aim stays off in multiplayer. The session mode can't be used for this: the port's online play runs as system link, just like Solo and Private Match. Lock-on and the auto-aim range are separate: the range is only used by auto-aim, and lock-on is not gated (there is no free space left in `t6mp.nro` for a second gate). A `t6mp.nro` with the old patch (`nop`) is converted by running the script again. The gate's source is `aim_gate/aim_gate.c`; `aim_gate/build.sh` rebuilds `aim_gate.bin` (needs zig).

## Bots in Party modes

`sd/switch/t6game/scripts/mp/party_bots.gsc` allows bots in Gun Game, One in the Chamber, Sticks & Stones and Sharpshooter. The "Setup Bots" button stays disabled in these modes: set the bot count and difficulty in a regular mode before switching. If the count is 0, 5 bots join (`party_bots_default_count()`).

## New launcher with settings (t6game.nro)

```
pip install pillow
launcher/build.sh /path/to/t6game.nro.original t6game.nro
```

Replaces the Requiem launcher with a custom one (libnx, `launcher/source`), with the same background look as the original and the options MULTIPLAYER, ZOMBIES, SETTINGS and UPDATES. The UI follows the console language: Portuguese when the system language is Portuguese, English otherwise. It builds in the `devkitpro/devkita64` container (docker). The assets (background, icon, fonts) are generated by `launcher/make_assets.py` from the original NRO and the macOS DIN Condensed Bold / Avenir Next Condensed fonts; on other systems, use `LAUNCHER_TITLE_FONT`, `LAUNCHER_TEXT_FONT` and the face indices.

On the SD card, rename the original launcher to `t6game_orig.nro`: the **UPDATES** item opens it, and it is what fetches and installs new versions (and can swap `t6game.nro` back to the official one).

In **SETTINGS**:

| Option | Where it is saved |
|---|---|
| Performance graph (DXVK HUD) | `dxvk-sarek.conf` (`dxvk.hud`) |
| In-game FPS counter | `cg_drawFPS` in `players/config_mp.cfg` and `config_zm.cfg` |
| V-Sync | `r_vsync` |
| Max FPS (30/60) | `com_maxfps` |
| Frames queued ahead (1-3) | `dxvk-sarek.conf` (`dxgi/d3d11.maxFrameLatency`) |
| Field of view (65-80) | `cg_fov_default` |
| Bots in Party modes | `return N;` of `party_bots_default_count()` in `scripts/mp/party_bots.gsc` |

With the HUD off and 1 frame queued ahead, `dxvk-sarek.conf` is deleted: without it the port already forces frame latency 1. When the file exists the port stops forcing it, so the launcher always writes the latency along with it.

## FPS counter with frametime

```
python3 patch_fps_counter.py /path/to/t6mp.nro
python3 patch_fps_counter.py /path/to/t6zm.nro
```

The counter enabled in Options → **Show FPS** (Mostrar FPS) then shows `60 fps  16.6 ms  max 33 ms`: FPS, average frametime and the worst frame of the last 32. A stutter shows up in `max` for about half a second. It can be applied together with the aim assist patch, in any order.

## Performance log (multiplayer)

```
python3 patch_perf_log.py /path/to/t6mp.nro
```

Without enabling anything in the game, `t6mp.log` gets a `[perf] t=... ms: N frames, avg ... ms, max ... ms, ...` line every 10 s (frames, average and max frametime, how many frames exceeded 20/34/50/100 ms, V-Sync, Max FPS, log write cost) and a `[perf] hitch N ms at t=... ms` line for each frame of 50 ms or more (at most 4 per 10 s). `t=` uses the same clock as the port's `[load]` lines. The source is `perf_log/perf_log.c`; `perf_log/build.sh` rebuilds `perf_log.bin` (needs zig). In `t6zm.nro` there is no space left after the FPS counter.

## Log without fsync per line

```
python3 patch_log_nofsync.py /path/to/t6mp.nro
python3 patch_log_nofsync.py /path/to/t6zm.nro
```

The port calls fsync after every `t6mp.log`/`t6zm.log` line, which costs about 17 ms on the SD card: any line logged during a match (bots picking classes, the `[perf]` summary) becomes a hitch. The patch removes that fsync from the host's log function; lines are still written immediately. The crash handler flushes the file on its own, so `[nx-crash]` reports are kept; only the last lines before a power-off or a pulled SD card can be lost. Works on both NROs and with the other patches, in any order.

## DXVK HUD (optional)

`sd/switch/t6game/dxvk-sarek.conf` enables the DXVK HUD with `fps,frametimes,gpuload,memory`, for when you don't use the new launcher (which writes this file from **Settings → Performance graph**). To turn it off by hand, delete the file.

## PT-BR menus

Use the official localization ported by Thermite: <https://github.com/ThermiteK/Call-of-Duty-Black-Ops-2-Port-da-Localizacao-em-Portugues-do-Brasil-Xbox-360-Playstation-3-para-PC/releases>. From the zip, inside `CoD_T6mp_T6zm_localizacao_Plutonium/Plutonium/storage/t6/`, copy:

- `raw/localizedstrings/` to `/switch/t6game/raw/localizedstrings/`
- `images/` to `/switch/t6game/images/`

The port reads the `.str` files from `raw/localizedstrings` (`_mp` files only in multiplayer, `_zm` only in Zombies).
